# Музыкальные подложки

Сюда кладутся **пять** файлов:

```
assets/music/bed1.mp3
assets/music/bed2.mp3
assets/music/bed3.mp3
assets/music/bed4.mp3
assets/music/bed5.mp3
```

Файлов в репозитории намеренно нет: чужая музыка в репозитории, который
может стать публичным, не нужна.

## Почему пять, а не одна

Ролик идёт сорок пять минут. Подложка длится две-три минуты и
зацикливается пятнадцать-двадцать раз; к двадцатой петле зритель знает её
наизусть, и она перестаёт быть фоном.

Поэтому:

- **в каждом ролике звучат ДВЕ подложки.** Вторая заходит примерно на
  середине через перекрёстное затухание в шесть секунд
  (`render.build_bed`). Смена сбрасывает привыкание целиком и стоит ноль;
- **соседние ролики не открываются одной музыкой.** Выбор идёт как у
  цветокора: две последних по журналу канала (`channel/log.json`)
  запрещены. Пять треков при глубине памяти два означают, что три
  загрузки подряд не могут начаться одинаково.

Что именно выпало — печатается при сборке и записывается в журнал:

```
  подложка: bed2.mp3, bed5.mp3, смена на 54% ролика, уровень -27.4 дБ
```

## Что подходит этому каналу

Ролик включают перед сном. Значит: без ударных, без резких вступлений, без
нарастаний к финалу, без вокала. Ровный тянущийся фон, в котором нечего
ждать — ожидание не даёт заснуть.

Уровень задаётся полем `bed_gain_db` в спецификации ролика; без него
движок берёт своё, от −29 до −25 дБ, тоже разное у каждого ролика. Чем
меньше число, тем тише. Отдельно подложка **уходит под голос** в
нескольких местах ролика (`duck_style` в векторе стиля) — это не
компрессия, а осознанные ямы на границах смысла.

## Своя музыка для конкретного ролика

```json
"music": "assets/music/bed3.mp3"
```

или сразу две, если хочется задать пару руками:

```json
"music": ["assets/music/bed3.mp3", "assets/music/bed1.mp3"]
```

Поле перебивает жребий целиком.

## Пока файлов нет

Сборка не падает. `build.py` пишет в лог

```
  ! подложек нет вовсе — собираю только с голосом
```

и собирает ролик с одной начиткой. Голос при этом всё равно проходит
нормализацию до −16 LUFS, так что тестовые сборки звучат так же ровно, как
готовые.
