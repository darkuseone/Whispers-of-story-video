# Ancient Whispers — конвейер сборки роликов

Канал смешанной тематики (расширен с августа 2026): древность и
археология, наука и космос, мифология, исторические расследования с
детективными нотками, «новый мир» — современные технологические и
цифровые феномены (теория мёртвого интернета, ИИ и так далее). Общий
тон — спокойное вечернее документальное расследование с интригой, не
только про древний мир. Без сенсационной шелухи — атмосфера, факты и
уважение к предмету разговора, каким бы он ни был. Ролики по
тридцать-сорок минут, их включают на ночь.

Конвейер собирает из текстового сценария готовый ролик и весь комплект для
выкладки. Работает в GitHub Actions без человека, кроме одного шага —
подтверждения материала.

Код снят с действующего проекта того же устройства — канала о находках и
аукционах. Что переделано под этот канал и почему, разобрано ниже и в
[`docs/ЗАДАНИЕ-ancient-whispers.md`](docs/ЗАДАНИЕ-ancient-whispers.md).
**Задание читать обязательно перед правками**: половина решений в коде
выглядит странно, пока не знаешь, что за каждым стоит.

## Что настроить

1. **Секреты.** Settings → Secrets and variables → Actions → вкладка
   **Secrets** (не Variables — их значения видны в логах):

   | секрет | зачем | обязателен |
   |---|---|---|
   | `ELEVENLABS_API_KEY` | озвучка | да |
   | `ELEVENLABS_VOICE_ID` | голос канала | да (или поле в спецификации) |
   | `MAGNIFIC_API_KEY` | 70% картинок, редкое видео, библиотека | хотя бы один из двух |
   | `XAI_API_KEY` | 30% картинок и всё зрение отбраковки | хотя бы один из двух |
   | `PEXELS_API_KEY` | стоковое видео | нет |
   | `PIXABAY_API_KEY` | стоковое видео | нет |

   Этап `material` работает и без единого ключа: шесть источников из
   восьми открыты (Wikimedia, Met, Art Institute, Cleveland, Openverse,
   Library of Congress, archive.org).

2. **Музыка.** Положить `bed1.mp3`…`bed5.mp3` в `assets/music`, см.
   [`assets/music/README.md`](assets/music/README.md). Пока файлов нет,
   ролик собирается с одним голосом и пишет об этом в лог.

3. **Слои поверх кадра.** Один раз выполнить `python pipeline/overlays.py`
   и закоммитить результат. Не сделать — не страшно: недостающий слой
   считается на месте при сборке, просто это минуты рендера каждый раз.

4. **Спецификация.** Скопировать `jobs/ancient-example.json` в
   `jobs/<имя>.json` и заполнить. Поля с подчёркиванием — комментарии,
   код их пропускает.

## Порядок работы

```
Actions → Build video → Run workflow
```

| stage | что делает | тратит деньги |
|---|---|---|
| `smoke` | синтетика + проверка монтажа, ни одного запроса наружу | нет |
| `material` | качает видео и фото, собирает листы отбора | нет |
| `vet` | только отбраковка по уже скачанному | центы (зрение) |
| `assets` | озвучка + генерация + материал | да |
| `render` | только монтаж из готового | нет |
| `auto` | всё подряд | да |

Правильный порядок для нового ролика:

1. `smoke` — проверить, что спецификация вообще собирается: длина блоков,
   главы, доли материала, сходимость таймлайна. Минуты, бесплатно.
2. `material` — посмотреть, что нашлось по запросам. Бесплатно, можно
   гонять сколько угодно, правя `footage_queries` и `archive_queries`.
3. Скачать артефакт **select-\<ролик\>**, посмотреть контактные листы,
   вписать номера негодного в `reject`.
4. `auto` — полная сборка.
5. Дальше правки монтажа гонять только через `render`: материал лежит в
   кэше, озвучка и генерация не повторяются.

## Отладка без ключей и без денег

```bash
python pipeline/mock.py  jobs/ancient-test.json   # тишина, карточки, testsrc2
python pipeline/smoke.py jobs/ancient-test.json   # проверки
python pipeline/build.py jobs/ancient-test.json   # настоящий монтаж
```

`mock.py` ничего не перезаписывает: настоящий материал, если он уже лежит
на месте, остаётся нетронутым.

**Проверять замером, а не глазом.** `build.py` в конце сам печатает длину
видео, длину звука, размер файла и доли материала по фазам. Расхождение
видео и звука больше полусекунды — это перекрытие переходов, и вылезает оно
молча: код возврата ноль, лог чистый, а конец начитки срезан.

## Чем этот канал отличается от канала о находках

Всё ниже — не вкусовщина, а следствия двух фактов: ролик идёт сорок пять
минут, и его включают перед сном.

### Цвет холодный

Тёплая янтарная семья (`warm_amber`, `oak_brass`, `lamp_glow`,
`dust_gold`, `copper_dusk`) убрана целиком. Два канала одного владельца
зритель сравнивает первым делом, и одинаковый грейд — самое заметное, что
между ними может совпасть.

| цветокор | характер | R−B на серой шкале |
|---|---|---|
| `moonlit_marble` | базовый: лунный камень | −13.3 |
| `nile_indigo` | индиго над рекой, самый ночной | −24.2 |
| `aegean_teal` | море и патина на бронзе | −18.9 |
| `temple_ash` | известняк, камень, пустыня | −6.4 |
| `starlit_lapis` | самый глубокий синий | −31.8 |
| `bronze_frost` | синяя тень, бронзовые света | +7.8 |

Отрицательное число означает, что серый уходит в синий; у тёплого канала
та же величина была от +10 до +25. `bronze_frost` разведён по температуре
сознательно — это египетская пара «золото на лазурите», и без неё шесть
одинаково синих цветокоров различались бы только на замере.

Архивная семья — `archive_platinum`, `archive_cyanotype`, `archive_stone`.
Разведена с основной не температурой, а плотностью: насыщенность в
два-четыре раза ниже, контраст выше.

Плёночная база `film_look()` тоже перевёрнута: синий поднимается вдвое
сильнее красного, тень уходит в лунный холод.

### Две фазы ролика

|  | вступление, 3-5 мин | тело, остальные 40 |
|---|---|---|
| видео | 70-80% времени, куски 3-8 с | 20-30% времени |
| изображения | 7-15 с | 70-80% времени, 10-40 с каждое |

Обе доли считаются по экранному **времени** и держатся на любом отрезке, а
не в среднем. Печатаются при каждой сборке:

```
  вступление   видео  76.9% (заказано 78%),  4.3 мин, 37 кадров
  тело         видео  21.1% (заказано 21%), 47.7 мин, 205 кадров
```

### Долгие кадры и долгие движения

Одна картинка держится до сорока двух секунд — но **никогда без
движения**. Обычный наезд на кадре в тридцать секунд отрабатывает за
первые десять и дальше стоит, поэтому в наборе появились ходы, которые
идут всю длительность: проезд через весь кадр, расширение из детали в
общий план, псевдопараллакс, «плавание» и дыхание.

Плюс форма кривой времени: у долгого проезда она обязана быть
**равномерной**, у сглаженной середина идёт вдвое быстрее краёв, и на
тридцати секундах это видно как рывок.

Проверяется дважды: `build.py` пересматривает движение на кадрах, которые
выросли против задуманного, а `rails.py` подтверждает результат на готовом
плане.

### Генерация — 40-50%, и она делится 70/30

На канале о находках генерации было 30%: там сюжет про конкретный предмет,
и рисованная монета выдавала бы себя за фотографию настоящей. Здесь речь
про мир, которого не сфотографировал никто — Фивы при жизни, ночь перед
битвой, Атлантида. Реального материала под такое не существует в природе.

```
    70%  Magnific  flux2pro, nano-banana2, seedream5pro (безлимит по подписке)
    30%  xAI       grok — как на соседнем канале
```

Делятся промпты **перемешанно**, а не первые 70% против последних 30%:
подряд идущий кусок означал бы, что вся вторая половина ролика нарисована
одной моделью. Внутри доли Magnific модели чередуются по кругу — три
генератора дают три почерка.

Через xAI видео не генерируется никогда.

### Видео из Magnific — только когда его нет

Короткие вставки 2-3 секунды (minimax-hailuo 2.3, kling 2.5, wan 2.2
— seedance 1.5pro не отозвалась ни на одно написание пути и из ротации
убрана, см. MISSING_MODELS в pipeline/magnific.py) добираются только тогда, когда футажа по теме не
нашлось вовсе. Потолок — 5% от нужного ролику видео плюс суточный лимит.
Сгенерированное видео узнаётся мгновенно, и чем его больше, тем быстрее
ролик читается как машинный.

Короткий клип на длинном кадре **замедляется**, а не зацикливается: петля
из трёхсекундного клипа читается как заедание.

### Библиотека Magnific — последняя очередь

Готовые видео, фото, векторы и графика берутся оттуда только по запросам,
где открытые архивы и стоки не дали **ничего**, и не больше 10-15 штук в
сутки. Счётчик суточный и общий на все ролики, лежит в
`channel/magnific_usage.json` и переживает раннер отдельным кэшем с ключом
по дате.

### Отбраковка строже

Три отличия от соседнего канала:

- **доверенных источников нет вовсе.** Там отсеивалось «не тот предмет», и
  музейный источник от этого спасал. Здесь отсеивается не та эпоха и не та
  цивилизация — Met честно отдаёт по слову «temple» храмы XIX века;
- **у видео проверяются два кадра**, начало и конец, а не один из
  середины: именно на краях живут заставки оцифровщиков и титры с адресами
  сайтов;
- **мало сказать «годится».** Модель ставит кадру оценку от 1 до 5, и
  кадр с оценкой ниже трёх не берётся: материала всегда больше, чем нужно
  ролику, а один чужой кадр виден зрителю все сорок пять минут.

Строже — не значит дороже. Платит зрение только за спорное, и с августа
2026 таким считается заметно меньше:

- **арифметика идёт по всем трём кадрам клипа.** Белая заставка архива и
  чёрный кадр на входе отбраковываются бесплатно — раньше ровно за них и
  платили, причём дважды: у видео спрашивается по два кадра;
- **близнецы спрашиваются по одному, дубли отбраковываются.** Один и тот
  же клип с Pexels и с Pixabay складывается в корзину по перцептивному
  хэшу — и второй экземпляр в ролик не идёт: потолок повторов считает
  показы одного файла, и дубль обходил его вдвое;
- **память вердиктов.** `vet_cache.json` рядом с материалом: ключ из
  промпта, темы, `vet_context` и порога оценки плюс отпечаток файла.
  Пересборка, в которой ничего из этого не менялось, зрению не платит
  вовсе, а правка `vet_context` пересматривает весь пул заново;
- **остановка по достатку.** Скачивается вчетверо больше, чем ролик
  покажет; как только годного набралось втрое больше нужного, остальное
  не смотрится. Считается по годным, а не по просмотренным, поэтому на
  плохом материале остановка просто не наступает.

Общие правила промпта (текст и логотипы, фэнтези-арт, дешёвая
реконструкция, нерелевантный сток, техническое качество) одни на весь
канал. А вот что здесь «своя эпоха», а что анахронизм — с августа 2026
у каждого выпуска СВОЁ: канал вышел за пределы античности, и жёстко
зашитое «отклоняй всё современное» ломало бы отбраковку на любом
выпуске про науку, расследования или «новый мир» — она бы браковала
собственный материал видео как «не тот период». Это описывается полем
`vet_context` в спецификации ролика (см. `pipeline/vet.py`,
`DEFAULT_PERIOD_CONTEXT`); не задано — работает старое поведение
«канал про древний мир», и вся античная линейка ведёт себя как прежде.

### Звук

Голос ровнее: `stability` 0.62 против 0.42, `style` в нуле. Плюс поле
`speed` для чуть более медленной начитки.

Подложек пять, в каждом ролике звучат две — вторая заходит на середине
через перекрёстное затухание. Причина арифметическая: трёхминутный трек за
сорок пять минут повторяется двадцать раз.

В самом конце ролик уходит в чёрное за шесть секунд: обрыв картинки на
полном свете будит. А после последнего слова идут ещё **четыре секунды
чёрного кадра без начитки** (`tail_hold` в спецификации, 3-6 секунд):
голос договорил, подложка уходит в ноль, дальше настоящая тишина. Без
этого хвоста озвучка обрывалась вместе с файлом, и на слух это щелчок.

### Два шортса из готового ролика

`pipeline/shorts.py` — этап 4, сразу после комплекта для YouTube. Режет
вертикаль 9:16 из уже собранного `final.mp4`, поэтому не стоит ничего:
ни озвучки, ни генерации, ни зрения.

Каждый шортс — вопрос плашкой сверху на весь ролик, кусок, в котором на
этот вопрос отвечают, и субтитры по тайм-кодам (шортсы смотрят без
звука). Заказываются в `youtube.shorts`:

```json
"shorts": [
  { "title": "Is Most Of The Internet Already Fake?",
    "question": "Is most of the internet already fake?",
    "anchor": "fifty-one percent of everything moving",
    "seconds": 42 }
]
```

`anchor` — точная фраза из `script_blocks`, вокруг неё и режется кусок.
Поле обязательное по смыслу: без него кусок ищется по словам вопроса и
почти всегда промахивается. Ненайденный якорь — ошибка, и её ловит
`smoke.py` до сборки, а не после трёх часов рендера.

### Плашки — на датах, а не на суммах

`textcard.py` теперь распознаёт «2600 BC», «третий век до нашей эры»,
«тысяча двести лет» и выводит их как `2600 BC`, `3RD CENTURY BC`,
`1,200 YEARS`. Добавлены два спокойных стиля: `carved` (разрядка, цвет
приглушён — надпись перестаёт быть титром) и `fade_slow`.

## Чтобы канал не выглядел конвейерным

YouTube показывает соседние загрузки канала рядом. Стиль ролика выпадает
случайно, но случайность без памяти регулярно даёт три похожих ролика
подряд.

Память ведёт `pipeline/channel.py`, журнал лежит в `channel/log.json`.

```bash
python pipeline/channel.py list                 # что уже выходило
python pipeline/channel.py check jobs/x.json    # не повтор ли это
python pipeline/channel.py record jobs/x.json   # записать ПОСЛЕ выкладки
```

| ось | как разводится |
|---|---|
| вектор стиля целиком | минимум 4 значимых отличия от каждого из 12 последних |
| тема | пересечение значимых слов, порог 34% на 8 последних |
| цветокор | 3 последних не повторяются |
| тип открытия | 2 последних |
| основной переход | 2 последних |
| слой поверх кадра | 2 последних, и примерно у трети роликов его нет вовсе |
| подложка | 2 последних |
| длина вступления, темп, зерно, виньетка | выпадают из диапазонов |
| раскладка превью | четыре варианта, выбирается по seed |

Записывать ролик в журнал надо **после выкладки**, а не после сборки —
иначе пересобранный десять раз ролик десять раз вытолкнет из списка
недавних настоящие.
